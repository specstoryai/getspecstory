# Grok Build provider review — PR #270

This is an implementation and QA review, with fixes made directly on `grok-build-provider`. The comparison branch is `dev`; the initial reviewed revision was `56d95b4`. The target release is **2.14.0, September 18, 2026**, supporting **Grok Build 1.0.34**. The installed baseline reports `grok 1.0.34 (3736acbc8658) [stable]`. Live checks are on macOS arm64.

The review follows [NEW-PROVIDER-REVIEW.md](NEW-PROVIDER-REVIEW.md), the [provider guide](../NEW-PROVIDER-GUIDE.md), the [SPI contract](../pkg/spi/provider.go), and the repository [PR review checklist](../.claude/commands/pr-review.md). The table records the source of each decision, rather than treating a sibling implementation or bot recommendation as sufficient proof.

**Status: review in progress.** The fixes below are implemented; full command-matrix QA, current-version tool auditing, reconstruction checks, factory enrollment, release documentation, and final CI verification remain open. This report will be updated as those checks finish.

## Numbered fixes and the source of the expected behavior

| # | Fix and user impact | Why a change was necessary: source of “right” | Evidence and validation |
|---|---|---|---|
| 1 | Normalize provider ID to `grok`, replacing `grok-build`. Saved provenance now uses the same identifier as CLI selection and registry lookup. | The [registry](../pkg/spi/factory/registry.go) registers `grok`; normalized provider identity must resolve to that registration. [Copilot finding](https://github.com/specstoryai/getspecstory/pull/270#discussion_r4039338014) identified the mismatch. | `TestGenerateAgentSession_Basic` asserts the registry ID in normalized output. Implemented in `e6dc180`. |
| 2 | Report normalized provider version as `unknown`, instead of attributing model name `grok-4.6` to the CLI application. | Guide, [Honest data over convenient data](../NEW-PROVIDER-GUIDE.md#honest-data-over-convenient-data), explicitly distinguishes application version from per-message model. [Copilot finding](https://github.com/specstoryai/getspecstory/pull/270#discussion_r4039337965). A live 1.0.34 `summary.json` records `current_model_id`, not application version. | The basic conversion test asserts `unknown`; native model fields remain on messages. Implemented in `e6dc180`. |
| 3 | Advance exchange end time when its final message is a backend web/X tool. | An exchange cannot end before its final timestamped message. The ordinary tool branch already advances this field; the backend branch omitted it. [Copilot finding](https://github.com/specstoryai/getspecstory/pull/270#discussion_r4039338056). | `TestBackendToolClosesExchange` ends a conversation with a timestamped backend tool and asserts that exact end time. Implemented in `e6dc180`. |
| 4 | Preserve distinct fallback prompt timestamps when update records omit `promptIndex`; never conflate them with valid index zero. Deduplicate chunks with a prompt ID where one exists. | Guide's honest-data requirement and native join semantics: a missing index is not zero. [Copilot finding](https://github.com/specstoryai/getspecstory/pull/270#discussion_r4039338089). The 1.0.34 capture confirms normal prompts carry `promptIndex`; the fallback concerns incomplete records, not a claimed older-version compatibility guarantee. | `TestMissingPromptIndexDoesNotCollideWithZero` interleaves known and missing indices and checks every recorded time. Implemented in `e6dc180`. |
| 5 | Make global enumeration, project listing, and detection read summary metadata and stop at the first real prompt, without reading the remaining transcript or sidecars. | [SPI `ListAllAgentChatSessions`](../pkg/spi/provider.go) specifies metadata-only discovery; reindex fetches full data separately. [Copilot finding](https://github.com/specstoryai/getspecstory/pull/270#discussion_r4039338131). The previous implementation performed the full parse twice for sessions selected by reindex. | `TestMetadataScanStopsAtFirstQueryAndSkipsSidecars` verifies one retained prompt, empty sidecar indexes, and metadata identical to full conversion. Implemented in `e6dc180`. |
| 6 | Use `spi.ReadRecordLine` and the shared 64 MiB record limit; skip oversized and malformed records and continue through the rest of transcripts and sidecars. | Guide's bounded-record requirement and [shared reader contract](../pkg/spi/jsonl.go) explicitly prohibit losing an entire session after one oversized record. Previous scanner cap was 250 MiB and aborted transcript reads, while sidecar scans stopped early. | Capped transcript and sidecar tests place valid records before and after an oversized line, including an unterminated final valid record. Implemented in `e6dc180`. |
| 7 | Build `RawData` from the accepted native records already parsed, preserving unknown fields. | Guide, [Honest data over convenient data](../NEW-PROVIDER-GUIDE.md#honest-data-over-convenient-data): a second native read can race an active agent and export raw turns absent from normalized data. Unknown fields are native evidence and must not be dropped by typed decoding. | `TestRawSnapshotAndDebugRefresh` changes the on-disk transcript after parsing; raw output still exactly matches the original accepted records, excluding malformed input. Implemented in `e6dc180`. |
| 8 | Debug export pretty-prints preserved native JSON and removes stale numbered records after a rewrite, while preserving CLI-owned `session-data.json` and honoring `debugRaw=false`. | Guide, [Native debug output](../NEW-PROVIDER-GUIDE.md#native-debug-output), requires readable native input, flag compliance, and refresh without stale records or deleting CLI-owned files. Marshaling typed structs had silently discarded native fields. | The same regression checks an unknown native field, a shrinking transcript, flag behavior, and an unchanged CLI-owned file. Implemented in `e6dc180`. |
| 9 | Replace local resume-argument manipulation with `spi.EnsureResumeFlagArgs`, so the selected session wins over a configured ID in either flag spelling. | Guide, [Run and exec](../NEW-PROVIDER-GUIDE.md#run-and-exec), explicitly requires this precedence and shared helper. Existing tests incorrectly asserted that the configured ID should win. | Updated table-driven resume tests assert replacement, bare/empty flag repair, preservation of unrelated arguments, and no caller-slice mutation. Implemented in `e6dc180`. |
| 10 | Add `Check` lifecycle logging and stop fabricating an `unknown` successful version when a binary prints no version. | Guide requires logged check decisions and says `CheckResult.Version` is the agent version string or empty; normalized `ProviderInfo.Version` has a different `unknown` rule. | Inspected one-outcome shared analytics calls and added start, lookup failure, probe failure, and success logs. Implemented in `e6dc180`; live command checks remain to be recorded. |
| 11 | Make watcher starts create fresh contexts; serialize start/stop, use `WaitGroup.Go`, and join callbacks before returning. | Guide watcher lifecycle requirements, [SPI callback contract](../pkg/spi/provider.go), and [Copilot finding](https://github.com/specstoryai/getspecstory/pull/270#discussion_r4039337911). A context canceled from `init()` could never support a second start. | `TestWatcherRestartAndShutdownDrain` exercises repeated start/stop cycles and verifies callback completion. Race-detector provider tests pass. |
| 12 | Establish a synchronous startup baseline, adopt late stores with old file times, reconcile all render-affecting sidecars, and perform a final disk reconciliation on shutdown. | Guide's watcher acceptance table defines unchanged startup, initialization races, late arrivals, unchanged shutdown, and final draining. The original watcher only flushed already-received fsnotify events and never reconciled file signatures, so it could miss fast first sessions, dormant-session changes, or final unread events. | Regression tests cover idle startup/shutdown, immediate final writes, startup sidecar changes, unwatched-session changes, and late creation through multiple missing ancestors with old timestamps. Race-detector provider tests pass. |
| 13 | Return watcher startup/runtime failures to callers instead of silently continuing without saving; use the shared panic-safe delivery helper. | Guide says watchers must not silently disable themselves and lists `spi.DeliverSession` as the shared delivery primitive. [SPI `WatchAgent`](../pkg/spi/provider.go) runs until error or cancellation. | `TestWatcherRejectsInvalidStore` verifies synchronous failure for a non-directory store; existing callback panic/nil tests pass through the shared helper. |
