# Grok Build provider review — PR #270

This is an implementation and QA review, with fixes made directly on `grok-build-provider`. The comparison branch is `dev`; the initial reviewed revision was `56d95b4`. The target release is **2.14.0, September 18, 2026**, supporting **Grok Build 1.0.34**. The installed baseline reports `grok 1.0.34 (3736acbc8658) [stable]`. Live checks are on macOS arm64.

The review follows [NEW-PROVIDER-REVIEW.md](NEW-PROVIDER-REVIEW.md), the [provider guide](../NEW-PROVIDER-GUIDE.md), the [SPI contract](../pkg/spi/provider.go), and the repository [PR review checklist](../.claude/commands/pr-review.md). The table records the source of each decision, rather than treating a sibling implementation or bot recommendation as sufficient proof.

**Implementation review complete: 48 numbered fixes, with local QA passing.** Merge recommendation: proceed when the [latest PR checks](https://github.com/specstoryai/getspecstory/pull/270/checks) are green and no new review finding remains unresolved. The reviewed code runs from initial revision `56d95b4` through `e293abc`; subsequent implementation changes require fresh verification. Native media and scheduler mutation success paths are unverified because the approved run exhausted the Grok account allowance before those calls. The remaining native-success coverage limits are listed below.

“Wrong” below means a demonstrated mismatch with an explicit user requirement, repository contract, observed native record, or acceptance test—not a preference for a different coding style. Copilot identified candidate defects; the contract or native evidence established whether they were defects. Rows 14 and 28 distinguish a regression introduced during this review and an existing shared CLI defect, respectively. The inventory includes changes made after the initial reviewed revision; it does not claim authorship of the original provider.

## What this suggests for the software factory

1. **Store the oracle with the test.** Keep the rule/contract link, exact agent version, sanitized native records, expected normalized data, and rendered artifact together. A test that merely ratifies existing output can preserve a bug (the old resume-ID and truncation assertions did).
2. **Use native declarations for inventory, actual call IDs for coverage.** A model said it exercised tools it never invoked. Reconcile IDs and native order, and track success/error/cancelled/pending/unexercised separately.
3. **Require real loader evidence for reconstruction.** Serializer round trips cannot establish that an agent accepts a file. Probe minimal required fields, recall, same-session continuation, and exact prepared-turn preservation.
4. **Exercise the lifecycle, not just event callbacks.** Test startup inactivity, writes during initialization, late directories with old timestamps, sidecar-only changes, bounded watches, shutdown drain, restart, and child exit errors. Windows disproved an otherwise plausible clock assumption.
5. **Gate on the current revision and completed review.** Record CI and review-thread state against a commit, including review-induced regressions. Recheck after fixes rather than reusing an earlier green run. Two findings arrived after the prior clean-thread check on `eb24709`; fixes 37–38 show why a momentary zero-open-thread result is insufficient while automated review is still running.
6. **Treat reviewer output as a lead.** Later Copilot findings exposed additional gaps, but the suggested alias expansion was rejected in favor of removing an unobserved alias. Requirements and evidence decide the remedy.
7. **Keep operational failures distinct.** Missing credentials, usage limits, sandbox restrictions, and unavailable native platforms are coverage limits; they must not become fabricated passes, silent “no change” factory readings, or invented compatibility defaults.
